# Банк вопросов для UX-процесса

Это не анкета — используй вопросы как отправную точку и распрашивай по ходу обсуждения.

---

## Общие вопросы о задаче

```
Как поняли, что появилась проблема?
Как она влияет на пользователей? Какие её последствия?
Когда она ударила в последний раз? Что произошло?
Пытались ли вы решить эту проблему? Какие способы пробовали? Что именно пошло не так?
На какие метрики повлияем?
Как сейчас пользователи выполняют эту функцию? Какой текущий флоу?
Проводились ли кастдевы? На основе чего собраны эти данные?
На что в первую очередь обращают внимание пользователи?
Как в будущем масштабировать экран? Какой функционал добавится?
У кого есть доступ к странице?
Можно задать вопросы по связанным процессам, частным случаям, корнер-кейсам?
Насколько сильно меняем продовую версию? Вносим коррективы или редизайним?
С какими проблемами могут столкнуться сотрудники после внедрения? Есть ли план?
Какой срок выполнения задачи?
Кто из фронтов возьмёт задачу?
Будет ли переписываться бэк?
Когда релиз задачи? Когда возьмут в разработку?
Будем ли проводить фронт-ревью этой задачи?
```

---

## Интерфейсные вопросы

```
Какие могут быть ошибки? Как их можно исправить?
Что будет идти из бэка, а что отрисовывается на фронте?
Что фильтруем? Как сортируем? Какая базовая сортировка?
Какие права доступа? Кто что видит?
Что происходит в пустом состоянии?
Что происходит при ошибке?
Какие состояния загрузки нужны?
```

---

## Вопросы по основанию задачи

### Основание: развитие бизнеса
```
Как задача связана с роадмапом продукта?
Какое масштабное будущее приближает эта задача?
Как соотносится со стратегией на этот год/квартал?
```

### Основание: аналитика
```
Какие данные есть? Откуда они?
Какие метрики страдают? Насколько критично?
Где наглядно видны текущие проблемы и риски?
Насколько данные достоверны и свежи?
```

### Основание: технические задачи
```
В чём техническая причина?
Что именно сломано логически?
Это legacy или оптимизация производительности?
Какие есть ограничения со стороны разработки?
```

### Основание: инициатива команды
```
Кто инициатор? Почему считает задачу важной?
На чём основано мнение — опыт, наблюдения, данные?
Кого ещё надо опросить, чтобы подтвердить гипотезу?
```

### Основание: обратная связь пользователей
```
Где собрана обратная связь? Опросы, мессенджеры, исследование?
Как часто проблема повторяется?
Кто именно страдает? Это большой или маленький сегмент?
Насколько проблема критична для пользователей?
Есть ли дополнительные данные в подтверждение?
```

### Основание: обратная связь техподдержки
```
Сколько тикетов по этой теме? За какой период?
Есть ли аналитика по тикетам или только ручные наблюдения?
Как поддержка сейчас решает эту проблему?
```

## Вопросы по типу задачи

### Улучшение старого
```
Как всё работает сейчас — опиши шаг за шагом.
Где именно пользователи спотыкаются?
Что работает хорошо и не стоит ломать?
Как должно работать в идеальном мире?
Какие технические ограничения нельзя обойти?
```

### Создание нового
```
Что мы точно знаем о пользователях и их потребностях?
Что мы предполагаем, но не проверяли?
Что мы не знаем и должны узнать?
Есть ли аналоги в других продуктах или у конкурентов?
Какова минимальная единица ценности для первого релиза?
```

### Концепт
```
Какую проблему он должен решать мощно и заметно?
Что вызовет восторг у пользователя?
Какие ограничения точно нельзя нарушать?
До MVP можно дойти позже — что будет в сильной версии?
```

### Исследование
```
Какой конкретный вопрос мы хотим ответить?
Какие гипотезы проверяем?
Какой метод лучше подходит для этого вопроса?
Сколько времени и ресурсов доступно?
Как решение на основе этого исследования будет выглядеть?
```

---

## Вопросы по целям и критериям успеха

```
Что именно должно измениться после решения задачи?
Как бизнес поймёт, что задача решена успешно?
Как пользователь поймёт, что продукт стал лучше?
Как разработчики поймут, что решение реализовано правильно?
Есть ли конкретные метрики, которые хотим улучшить?
Каков приемлемый результат через 3 месяца после релиза?
Что является провалом?
```

---

## Вопросы по исследованию

```
Что именно проверяем?
Какие гипотезы или вопросы покрывает это исследование?
Какой метод выбираем: интервью, юзабилити-тест, A/B, опрос, дневниковое исследование?
Сколько участников нужно?
Какие критерии отбора участников?
Как зафиксируем результаты?
Какие рекомендации ожидаем получить?
```

---

## Вопросы по тестированию

```
Что тестируем — прототип, финальный макет, реализованный продукт?
Формат: внутренняя проверка, юзабилити-тест, A/B-тест?
Кто участники тестирования?
Какие сценарии проверяем?
Что считаем критической ошибкой?
Когда тест, кто проводит, как фиксируем результаты?
```

## Вопросы по handoff

```
Все ли артефакты готовы к передаче?
Есть ли открытые вопросы к фронту?
Есть ли открытые вопросы к бэку?
Есть ли вопросы к QA?
Что нужно объяснить разработчикам отдельно?
Есть ли анимации, состояния или поведения, которые сложно понять из макетов?
Когда задача берётся в разработку?
```
